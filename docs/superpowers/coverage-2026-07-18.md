## 2. Desktop exclusion list (Wails-runtime-dependent / non-hermetic)

| Function | Why excluded |
|---|---|
| `startup` | Spawns a goroutine that calls `a.backupMgr.CleanOld` against the **real** `os.UserHomeDir()` with no injectable seam — testing it would perform real I/O against the developer/CI machine's home directory (non-hermetic, side-effecting). |
| `runScan` | Goroutine body of `StartScan`; calls `wruntime.EventsEmit(a.ctx, ...)`. Verified against wails v2.13.0 source (`pkg/runtime/runtime.go`'s `getEvents`): without a real Wails frontend bound into `ctx` (`ctx.Value("events")`), it calls `log.Fatalf`, i.e. `os.Exit(1)` — which would kill the entire test binary, not just fail one test. |
| `runClean` | Same reason as `runScan` (`wruntime.EventsEmit` calls for `backup:progress`/`clean:progress`/`clean:done`). |
| `runUninstall` | Same reason (`wruntime.EventsEmit` for `uninstall:progress`/`uninstall:done`). |
| `runTMClear` | Same reason (`wruntime.EventsEmit` for `maintenance:progress`/`maintenance:done`). |
| `StartScan` success path | The synchronous "already running" / "no valid ids" error branches ARE tested; only the branch that does `go a.runScan(...)` is excluded, since exercising it reaches `runScan`'s `os.Exit(1)` risk above. |
| `StartClean` success path | Same as above, for `go a.runClean(...)`. |
| `StartUninstall` success path | Same as above, for `go a.runUninstall(...)`. |
| `StartTMSnapshotsClear` success path | Same as above, for `go a.runTMClear(...)`. |
| `OpenFDASettings` | Shells out to `/usr/bin/open <FDA settings URL>`, which would visibly launch macOS System Settings on the machine running the test — a real, disruptive side effect, not just a Wails dependency. |
| `RevealInFinder` | Shells out to `/usr/bin/open -R <path>`, which would visibly open a Finder window on the test machine. |
| `CopyPath` | Calls `wruntime.ClipboardSetText(a.ctx, ...)` — same `os.Exit(1)`-on-fake-context risk as the `run*` functions above, and would also mutate the real system clipboard if it somehow didn't exit first. |
| `main.go`'s `main()` | Process entrypoint; wires the real Wails app lifecycle (`wails.Run(...)`) — not unit-testable without actually launching the GUI app. |
| `tools/genicon/*` | A standalone build-time icon-generation CLI tool, unrelated to `App`'s bound-method surface — out of this task's scope (the brief's candidate list is entirely about `App`/pure engine helpers). |

**One deliberate divergence from the brief's suggested list:** the brief
grouped `CheckFDA` with `OpenFDASettings`/`RevealInFinder`/`CopyPath` as
"shell/clipboard calls." On inspection, `CheckFDA` → `fda.Check(a.home)` only
does `os.ReadDir(home + "/Library/Safari")` — no shell-out, no clipboard, no
Wails runtime dependency. With a temp `home` (no `Library/Safari` dir), the
probe fails with `ENOENT` (not `EPERM`/`EACCES`), so `fda.Check` deterministically
returns `nil` (the tri-state "unknown" result) — headless-safe and
non-flaky. It is tested in `TestCheckFDA_UnknownWhenSafariDirMissing`
(`apps/desktop/app_test.go`) rather than excluded.

## 4. How to re-run

```sh
# Desktop (Go) — coverage profile + function table
cd apps/desktop && go test ./... -coverprofile=/tmp/desktop.out && go tool cover -func=/tmp/desktop.out

# Frontend — coverage report (requires @vitest/coverage-v8, added this task)
cd apps/desktop/frontend && npx vitest run --coverage

# Everything green (Step 4 of the task brief)
cd packages/engine && go test ./...
cd apps/desktop && go test ./...
cd apps/cli && go test ./...
cd apps/desktop/frontend && npx vitest run && npx tsc --noEmit
```

Frontend coverage scope is controlled by `apps/desktop/frontend/vite.config.ts`
(`test.coverage.include: ['src/**']`), which is what keeps `wailsjs/`
generated bindings out of the ≥80% target's denominator.
